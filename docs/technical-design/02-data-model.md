# Data model

## Conventions
Time-ordered UUIDs generated by the app. `timestamptz` in UTC. Every tenant table has `organization_id NOT NULL`. Text columns with CHECK constraints instead of enums. Emails normalized (trimmed, lower-cased) for comparison, original kept. Secrets encrypted by the app with a key id stored beside each value.

## Tables
**Identity and tenancy:** `organizations` (name, logo, default sender name, reply-to, time zone, status, require_approval, retention_days, storage_quota_bytes default 20 GB, optional caps and caps_enabled), `users` (one organization, email unique system-wide, role, status, argon2id hash, encrypted TOTP seed, hashed recovery codes, lockout), `operators` (platform admins, no organization, separate table), `invitations`, `auth_tokens` (hash only), `sessions` (token hash, expiry, mfa flag), `labels` and `label_assignments` (M1).

**Providers:** `email_providers` (host, port, tls_mode, username, encrypted password plus key id, fixed From address, is_default with partial unique index, status `active|needs_attention|deactivated`, daily/minute/hour limits, `config_version`), `provider_usage` (budget counters per window).

**Templates:** `templates`, `template_versions` (immutable: subject, html, text, variable_settings), `template_assets` (inline images).

**Campaigns and data:** `campaigns` (type, state, template_version_id, provider_id, strictness, dedupe settings, attachment mode, schedule UTC plus time zone, launched_at, frozen_provider_version, declaration, approval fields for M1, pause/attention reasons, cached totals, purge dates), `imports`, `campaign_recipients` (the queue: row number, email, normalized email, mapped values jsonb, attachment names, state, reasons, attempt_count, next_attempt_at, lease_expires_at, current_attempt_id, accepted_at, message_id; unique on campaign + row number; partial index on queued rows by due time), `send_attempts` (append-only), `campaign_attachments`, `validation_issues`, `campaign_outcome_totals` (kept after purge).

**Other:** `suppression_entries` (organization, normalized email, scope `non_transactional|all`, source, unique on organization + email + scope), `notifications`, `system_emails` (outbox), `audit_log` (append-only, monthly partitions, organization null for operator actions), `support_grants` (M1), job library tables.

## Tenant isolation
1. RLS enabled and **forced** on every tenant table. Policy: `organization_id = current_setting('app.org_id')::uuid`. The app role is not the owner, not superuser, no bypass.
2. Composite foreign keys on (organization_id, id) so cross-tenant references are impossible.
3. CI guard test reads the catalog and fails if a table with `organization_id` lacks forced RLS, a policy, or composite FKs.
4. A separate narrow role for scheduler, sweeper and purge with explicit policies. Operators have no policy reaching tenant content (M1 adds support grants).

## Snapshot at launch (no copying)
Template versions are immutable. Recipients and attachments are locked at launch (only Failed or Pending rows editable, audited). The campaign stores `frozen_provider_version`; if `email_providers.config_version` differs, the campaign moves to Needs Attention. Mapping and settings are copied into the campaign at launch.

## Retention purge (M1)
One transaction writes `campaign_outcome_totals`, deletes recipients, attempts and issues, deletes storage objects (retry until gone), marks `purged_at`, writes an audit entry with counts only. After a backup restore the purge is re-applied.

## Unsubscribe token
Opaque, encrypted, self-contained token (organization, normalized email, campaign, key version), sealed with an AEAD purpose key. No token table. Valid after purge. Tampered tokens fail to open.
